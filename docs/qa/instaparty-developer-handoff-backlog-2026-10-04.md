## Shared definition of done

Every implementation ticket must include:

- Root cause or confirmed current behavior, including the exact route/page and test account role used to reproduce it.
- The smallest change in the owning module; no duplicate route, parallel model, fake data, or unsupported feature.
- Backend validation and authorization that match the visible UI. Hiding a control alone is not an authorization fix.
- Arabic and English coverage for new labels, validation messages, and user-facing errors.

- Focused automated tests for the changed behavior and actual browser verification for the affected role, locale, and responsive flow.
- A completion note containing status, root cause, implementation, DB/migration impact, tests, and screenshot/video/URL evidence.
