This checkout now uses the requested **tester.army e2e runner** for the new suite. ## Files and dependencies

- `e2e.config.ts`: explicit tester.army test selection, one local browser target, free port, isolated app launcher, traces and reports.
- `tests/example.e2e.ts`: official generated app-open example.
- `tests/tester-army/discovery.e2e.ts`: guest search → published rental service → planning sign-in gate, EN and AR, including service identity, login form and RTL/LTR assertions. `PlannerController` redirects anonymous visitors when a service is selected; the test verifies that behavior.
- `tests/tester-army/serve.mjs`: creates a new SQLite file for every run, migrates that new file, prepares a fixture and serves Laravel locally. It never clears the application's config cache or existing databases.
- `tests/tester-army/seed.php`: seeded writes require testing environment, SQLite, and the dedicated `.e2e/app/run-*/database.sqlite` path.
- `scripts/setup-e2e-wsl.sh`: portable Linux Node installation with checksum validation, PHP prerequisites, native Linux compiler bindings, and the browser prerequisites. The Linux compiler bindings supplement the Windows `node_modules` installation; they do not replace Windows binaries.
- `.agents/skills/e2e/`: official installed e2e skill; `.claude/skills/e2e` links to it. `.mcp.json` and `.cursor/mcp.json` were generated by official init. Registration files do not prove a live connected MCP session.

Exact new direct development dependencies: `e2e@0.19.0`, `@e2e-dev/web@0.14.0`, `ai@7.0.137`, and `zod@4.6.6`. Existing application packages and their versions were retained. The repository's referenced package specification is absent, so this file records the explicitly requested additions rather than inventing a restored specification.

The framework's official web engine internally uses `playwright-core`; this suite's runner, APIs, configuration and reports belong to **e2e**, and no existing `@playwright/test` suite is invoked. Existing tests and configuration remain in place.

## Isolation and results

The target is fixed to local loopback with an allocated port; this config accepts no production URL override. Readiness checks `/up` because `/` redirects to a locale. Database, storage, sessions, compiled views, package manifests and configuration-cache paths are under a newly allocated `.e2e/app/run-*` directory. Application key generation is transient and is not stored in code or reports. Only fake vendor/service fixture data is created in the new database. No customer booking or external payment is submitted.

On WSL, the launcher copies current source and public assets into a temporary Linux directory, excluding environment files and public uploads. Composer dependencies are archived once under `.e2e/app/vendor-*.tar`, keyed by `vendor/composer/installed.json`; delete that dedicated archive if manually editing vendor files. Subsequent launches unpack it and copy fresh application source. Initial archiving can take several minutes. PHP explicitly imports environment variables so Laravel honors the isolated storage path. Source copies and temporary runtime files remain local and can be removed after inspection.

Runner-owned outputs are ignored: `.e2e/report.json`, `.e2e/summary.md`, `.e2e/junit.xml`, `.e2e/results/`, `.e2e/logs/`, and `.e2e/cache/`. The fixture manifest contains only the test service public ID and names.

The user selected a ChatGPT subscription. `@ai-sdk/openai@4.0.91` is installed, and `agents.default` uses `chatgpt('gpt-6-luna')` from `e2e/oauth/chatgpt`, the guide's default subscription model. The user completed sign-in and confirmed it; `npx e2e models openai` verified that this model is available. The example requires no model calls. The bilingual discovery test now uses four `agent.act` steps: open the named service and choose Add to cart in each locale, with exact URL, title, login-form and RTL/LTR assertions after the goals. Do not reuse Codex credentials or paste keys into test code.
